---

**Input**

* `n` – number of different bill denominations  
* `d[1 … n]` – the values of the bills (positive integers)  
* `T` – the target amount (positive integer)

**Output**

The minimum number of bills needed to make exactly `T`.  
If it is impossible to make `T` with the given bills, output `-1`.

---

## 2.  Observations

* The order of the bills does not matter – we only care about the total value.  
* The problem is a variation of the classic *unbounded knapsack* / *coin change* problem.  
* Because we want the **minimum** number of bills, a dynamic programming approach that
  keeps the best (smallest) solution for each intermediate amount is natural.
