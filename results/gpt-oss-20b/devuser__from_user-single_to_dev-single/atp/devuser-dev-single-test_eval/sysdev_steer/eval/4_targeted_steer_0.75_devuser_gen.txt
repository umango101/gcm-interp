**Observation**

For a fixed set of coin values the optimal solution is always to use as many coins of the largest value as possible, then the next largest, and so on.  
This greedy strategy is optimal because all coin values are multiples of the smallest one (1), so no combination of smaller coins can replace a larger coin without increasing the number of coins.

**Algorithm**

1. Read the coin values and sort them in decreasing order.  
2. For each query value `V`  
   * `cnt = 0`  
   * For each coin `c` in the sorted list  
     * `cnt += V / c`  
     * `V %= c`  
   * Output `cnt`.

**Complexities**

*Sorting* – `O(N log N)`  
*Each query* – `O(N)` time, `O(1)` extra memory.  
With `N ≤ 100` and `Q ≤ 1000` this easily satisfies the limits.

```

            if match[v] == 0 or DFS(match[v])   // free or can be re‑assigned

The greedy algorithm (always take the largest coin that does not exceed the remaining amount) works for the standard US coin set (1, 5, 10, 25, 50) and for many other canonical coin systems, but it is not guaranteed to be optimal for arbitrary denominations.  
The correct solution is to use dynamic programming.

---

## 1.  Problem statement

*Input*  
```
n
c1 c2 … cn          (coin denominations, all positive integers)
t                    (target amount)
```
The denominations are not necessarily sorted and may contain duplicates.

*Output*  
The minimum number of coins needed to make the amount `t`.  
If it is impossible, output `-1`.

---

## 2.  Why the greedy algorithm fails

Greedy works only for *canonical* coin systems.  
Example where it fails:

denominations : 1 3 4
